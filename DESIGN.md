# ANEI Creative Direction

## Product identity

ANEI is a professional inclusive-education platform.

It should feel closer to a modern educational institution than a generic technology startup.

The visual identity must communicate:

- credibility
- expertise
- accessibility
- warmth
- professionalism
- academic seriousness
- modernity
- human connection

## Three visual experiences

ANEI contains three distinct experiences.

### Public website

The public site should feel:

- editorial
- institutional
- human
- spacious
- trustworthy
- content-led

Use strong typography, photography, structured whitespace, and clear calls to action.

### Learner LMS

The learning experience should feel:

- focused
- calm
- productive
- motivating
- easy to scan

The interface should prioritize:

- continue learning
- current progress
- upcoming learning activities
- certificates
- course navigation

Avoid marketing-style decoration inside the LMS.

### Admin Console

The admin experience should feel:

- enterprise-grade
- operational
- precise
- dense but readable
- professional

Use:

- dedicated sidebar
- compact metrics
- powerful tables
- filters
- clear page headers
- meaningful charts
- contextual actions

The admin must not look like the public website.

## Visual language

Preferred:

- institutional cobalt/blue
- deep navy
- neutral slate
- white
- warm neutral surfaces
- restrained semantic colors

Use semantic design tokens.

Avoid arbitrary colors inside components.

## Typography

Typography should establish hierarchy before decorative containers.

Use:

- strong but restrained display headings
- highly readable body typography
- compact labels
- clear metadata hierarchy

Avoid:

- giant startup headlines
- unnecessary all-caps text
- decorative typography
- excessive font weights

Arabic typography must be treated as a first-class design requirement.

## Layout

Prefer:

- editorial asymmetry where appropriate
- strong grid systems
- intentional whitespace
- varied section composition
- clear alignment
- disciplined spacing

Avoid repeating:

three cards
three cards
three cards

throughout every page.

Avoid excessive nesting of cards.

## Surfaces

Use cards only when content genuinely benefits from containment.

Prefer hierarchy through:

- spacing
- typography
- alignment
- background changes
- dividers

before adding:

- borders
- shadows
- floating cards

## Corners

Use restrained corner radii.

Avoid extremely rounded SaaS-style containers.

Buttons, inputs, cards, dialogs, and tables should use a consistent radius system.

## Shadows

Use subtle elevation only when it communicates hierarchy.

Avoid heavy floating shadows.

## Photography

Photography should feel documentary and authentic.

Preferred subjects:

- educators
- inclusive classrooms
- professional teacher training
- collaboration
- accessibility
- digital learning
- educational workshops
- certification and professional development

Avoid:

- generic corporate meetings
- handshake imagery
- fake startup teams
- AI robots
- abstract AI brains
- overly staged stock photography

Photography must support the story rather than fill space.

## Iconography

Use one consistent SVG icon system.

Prefer existing project icons or Lucide if already installed.

Avoid emoji.

Avoid mixing multiple icon styles.

## Motion

Motion intensity: restrained.

Use motion for:

- navigation
- menu state
- dialogs
- accordions
- hover feedback
- progress
- loading states
- meaningful transitions

Avoid decorative continuous animation.

Animations should normally feel fast and subtle.

Respect prefers-reduced-motion.

## Data visualization

Admin charts should communicate real information.

Preferred:

- line charts for time trends
- bars for comparison
- limited donut charts for simple distribution

Avoid:

- 3D charts
- decorative charts
- charts with fake data
- too many chart colors

## Forms

Forms should feel calm and trustworthy.

Always use:

- visible labels
- clear validation
- helpful error messages
- appropriate input sizes
- obvious primary actions

Do not rely on placeholder text as labels.

## Responsive behavior

Design mobile intentionally.

Do not simply scale desktop layouts down.

Important breakpoints for visual review:

375px
768px
1024px
1280px
1440px

## RTL

Arabic must use genuine RTL layout.

Audit:

- navigation
- sidebar
- tables
- pagination
- breadcrumbs
- forms
- icons
- charts
- dialogs

Do not blindly mirror directional icons.

## Accessibility

Target WCAG 2.2 AA.

Accessibility is part of the design quality, not a final patch.

## Anti-AI design rules

Avoid common AI-generated UI patterns:

- purple gradient hero sections
- glowing buttons
- random gradient text
- excessive pill labels
- oversized rounded cards
- every section inside a card
- identical three-column sections everywhere
- floating decorative dashboard mockups
- arbitrary blobs
- fake testimonials
- fake metrics
- excessive glassmorphism
- visual complexity without functional purpose

## Design principle

ANEI should look intentionally designed for its actual educational mission.

Do not optimize for novelty.

Optimize for:

clarity
credibility
humanity
usability
consistency
