# Threat model

Method: asset/threat review aligned to current OWASP web-application risks and ANEI business logic. Likelihood/impact are qualitative and must be revisited after real hosting topology and traffic are known.

| Asset | Threat | Attack surface | Likelihood | Impact | Existing controls | Missing/operational controls | Mitigation/test status |
|---|---|---|---|---|---|---|---|
| User accounts | Credential stuffing / session theft | auth endpoints, cookies, reset flow | medium | high | Better Auth, HTTPS requirement, rate limits, secure cookies, short session-cache TTL, revocation UI | alerting, real provider acceptance, optional MFA policy | staging auth abuse tests + session revocation tests required |
| Admin accounts | Vertical privilege escalation | `/api/admin/*`, role mutation | medium | critical | server RBAC, SUPER_ADMIN-only roles, final-super-admin protection, audit | MFA/recovery, privileged alerting | anonymous baseline automated; cross-role staging regression required |
| Paid learning | IDOR / entitlement bypass | learning/resource/webinar routes | medium | high | user-bound enrollment/purchase joins; protected resource route; server session | exhaustive two-user test matrix | automate and manually retest every new protected object |
| Certificates | Forged completion | progress API, certificate issuance | medium | high | server derives lesson completion, transactional course progress, unique certificate | assessment/verified learning policy if high assurance required | tampered-progress and completion business-logic tests |
| Orders/payments | Price/provider manipulation, replay | checkout, return, webhook, admin reconcile | medium | critical | server price, integer millimes, provider verify, reference/amount check, idempotency, DB transaction | official sandbox acceptance/reconciliation alerts | Flouci success/fail/replay/mismatch tests before launch |
| Database | SQL injection / integrity bypass | search/forms/admin APIs | low-medium | critical | Zod, Drizzle parameters, no unreviewed `sql.raw`, DB checks/uniques | least-privilege production DB role, DAST | static + integration + staging injection payloads |
| Browser/user content | Stored/reflected/DOM XSS | news, bios, descriptions, support inputs | medium | high | React escaping, no raw HTML baseline, CSP | rich-content sanitizer if HTML is introduced; browser DAST | source regression + manual/ZAP staging tests |
| State-changing APIs | CSRF / sibling-origin abuse | custom cookie-auth mutations | low-medium | high | exact Origin/Referer + Fetch Metadata policy, SameSite/Auth protections | real proxy/domain staging validation | foreign-Origin E2E exists; same-site sibling case unit-tested |
| Server network | SSRF | future URLs/importers/AI tools | low now | high | no arbitrary remote URL fetch in current business features; provider URLs server-configured | URL/IP allowlists for future fetch tools | mandatory review before any URL-fetch/AI tool feature |
| Object storage | Malicious/spoofed upload / public leak | admin direct upload, bucket IAM | medium | high | admin RBAC, MIME allowlist, presigned POST content-length/type policy, random keys, private signed GET | malware scan/quarantine, media transcoding, provider IAM/CORS test | partial; production pipeline required before broad untrusted uploads |
| Secrets | Leakage/abuse | env, logs, CI, provider config | medium | critical | `.gitignore`, env validation, redacted logs, no browser secrets, secret-manager requirement | real secret scanner + rotation drills | CI/platform scan and incident drill required |
| Availability | Flood / expensive queries | auth/contact/search/progress/checkout | medium | medium-high | Redis limits, bounded bodies, DB pool cap, pagination/indexes | WAF/DDoS, metrics/alerts, tuned limits | bounded k6 staging profile + provider-mocked load test |
| Supply chain | Malicious/vulnerable dependency | npm/build/container/CI | medium | high | exact critical dependency versions, CI audit, CodeQL, Dependabot, non-root image | committed lockfile, SBOM/container/secret scan results | blocking release gate until lock + scans are green |
| Logs/audit | Tampering / sensitive leakage | application logs, admin audit | low-medium | high | redaction helper, audit records, restricted server access | centralized immutable retention/alerts | operational control required |
| Backups | Loss/ransomware/failed restore | PostgreSQL/storage backups | low-medium | critical | documented backup/PITR/restore process | real encrypted off-site backups + restore drill | deployment blocker before launch |
| AI (future) | Prompt injection/data exfiltration/tool abuse | chat, RAG, agent tools | high if enabled | critical | production flag fails closed; contracts separate authorization | retrieval ACLs, tool allowlist, quotas, red-team/evals | do not enable until AI security plan is implemented |
